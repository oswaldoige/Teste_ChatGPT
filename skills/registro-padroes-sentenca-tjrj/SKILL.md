# Registro Padroes Sentenca TJRJ

## Workflow

1. Confirm that there is an approved matrix, paradigm, or sentence family already accepted by the user.
2. Compare the new case with the existing canonical models in:
   `modelos`
3. Classify the situation into one of three outcomes:
   - only reuse an existing canonical model;
   - refine an existing recurring hypothesis;
   - create a new recurring hypothesis with its own canonical model.
4. When the hypothesis is new or has evolved materially, read [fluxo.md](references/fluxo.md) and [template-registro.md](references/template-registro.md).
5. Update the registry file of the corresponding family, recording at least:
   - short name of the hypothesis;
   - macrofamily and subfamily;
   - central controversy;
   - recurring factual markers;
   - drafting keys;
   - typical result;
   - canonical model path;
   - reusable block path;
   - example process numbers.
6. If the recurring hypothesis needs its own sentence matrix, create or update the canonical `.docx` in the proper family folder and keep the gabinete phrasing as close as possible to the approved paradigm.
7. If the standardization is concentrated in one or two reasoning bridges, create or update a reusable text block instead of proliferating full models.
8. After registering the hypothesis, return to the case-specific drafting flow and use the new canonical model as the primary matrix.

## Output Expectations

- Preserve the gabinete style and avoid free rewriting when the user has already approved a concrete matrix.
- Treat the registry as operational memory, not as a loose note file.
- Record only hypotheses that are materially recurrent or likely to recur.
- Prefer one strong canonical model plus one reusable block over multiple near-duplicate models.
- In consumer sentences, respect the procedural rule that the sentence must not newly defer inversion of the burden of proof.

## Resources

- Read [fluxo.md](references/fluxo.md) for the storage paths and decision tree.
- Read [template-registro.md](references/template-registro.md) for the exact template of each new hypothesis entry.

This skill turns approved gabinete phrasing into reusable operational memory. It exists so that materially semelhantes controversies stop being redrafted from scratch and start being resolved from a registered family model with stable redação, dispositivo cadence, and reusable reasoning bridges.

## When To Trigger

- The user says that a new sentence should follow the same standard as an approved prior sentence.
- The controversy is materially recurrent and the local nucleus still lacks a clearly cataloged hypothesis for it.
- A family already exists, but the new case reveals a stable variant that deserves its own canonical sentence matrix or reusable block.

## Classification Rule

1. **Same family, same skeleton**:
   update only the registry and reuse the existing canonical model.
2. **Same family, new stable reasoning bridge**:
   create or refine a reusable block and keep the canonical model count restrained.
3. **New repetitive hypothesis with its own dispositive rhythm**:
   create a new registry entry and a new canonical `.docx`.

## Minimum Deliverables

- A clean registry entry in the correct family file.
- A canonical model path or an explicit decision to keep using an existing one.
- A reusable block whenever the standardization is concentrated in one or two paragraphs.
- The process-specific draft regenerated from that registered matrix.

## Redaction Guardrails

- Preserve the gabinete phrasing already approved by the user whenever there is a concrete matrix.
- Prefer continuous prose with the same connective rhythm of the approved paradigm.
- Do not invent a new architecture if the controversy already fits an existing sentence family.
- In consumer cases, do not write as though the sentence were freshly deferring inversion of the burden of proof.
- Before final delivery, ensure the generated `.docx` reopens without mojibake or broken PT-BR punctuation.
